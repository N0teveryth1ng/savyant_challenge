# AI Usage Disclosure

## Overview

OpenAI Codex (ChatGPT) was used as a development assistant for this assignment. The work was directed by me: I supplied the assignment requirements, chose the project scope and preferred coding style, reviewed the generated changes, tested the application, and asked for corrections when behavior or readability did not match what I wanted.

AI was used as a tool within a human-led implementation process. I did not ask it to make product decisions independently or submit an unreviewed result as my own understanding.

## My contribution

- I defined the expected behavior by translating the assignment into concrete customer, product, order, stock, report, CSV, and test requirements.
- I designed and built the core application behavior and main business functions. I wrote the original customer and product CRUD functions in the customer and product services; AI later helped revise and extend those files to meet additional requirements.
- I chose the simple router/service structure and repeatedly guided implementation toward code that I could read and explain.
- I directed the setup and database work, including the required entities, fields, relationships, sample data, and local MySQL use. I configured and checked the local database connection and verified the database state while working through the assignment.
- I reviewed the features, ran the application and tests, reported problems I observed, and requested targeted corrections. I also made decisions about what sample data to retain during local testing.

## AI-generated and AI-assisted work

### Frontend

The frontend was generated by AI from my instructions. This includes the page structure in `app/templates/index.html`, styling in `app/static/styles.css`, and browser behavior in `app/static/app.js`: forms, tables, role-aware controls, order item rows, live total previews, API calls, messages, and confirmation prompts. I directed what the interface should do, reviewed it in the browser, and requested changes to keep it aligned with the assignment and the backend.

### Project setup and database support

AI generated and revised much of the initial project scaffolding and local setup resources, including the FastAPI entry point and configuration, database connection support, environment example, SQL schema, sample records, and the migration for the existing local database. These were produced under my direction: I specified the required stack and data model, configured the local MySQL connection, and checked the resulting tables and application connection.

### Backend assistance

The original customer and product CRUD functions and the core application behavior were my work. As the assignment requirements expanded, AI also helped implement or revise specific backend features and integrate them with the existing application, including:

- Backend permissions for administrators and sales users.
- Order totals, Draft order handling, server-side product price lookup, and order-number support.
- Stock confirmation and cancellation, including transaction handling and stock movement records.
- Report queries and their API routes.
- CSV validation, all-or-nothing imports, and opening-stock movement records.
- API wiring and frontend-to-backend integration.

These changes were reviewed against the requested behavior and adjusted to fit the existing schema, naming, and straightforward coding style.

### Tests and documentation

AI helped prepare and revise pytest coverage for the required calculation, order, access, stock, and CSV scenarios. It also assisted with the README, SQL report queries, migration notes, and this disclosure. I ran the test suite and used failures and browser/database behavior to guide corrections.

## Review process

I reviewed the work against the assignment instructions and checked the application using the local database. The test suite was run with `pytest -v`; all 20 tests passed at the time of the final implementation review. The test fixture uses the separate `sales_inventory_test` database.

I asked for explanations and simpler versions when code was difficult to follow, checked database behavior directly, and corrected implementation details through follow-up requests. I am responsible for understanding the submitted work and being able to explain, debug, and modify it.
